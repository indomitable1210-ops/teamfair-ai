## 1. 문제 정의 — 팀플 현장의 Pain Point

대학 팀 프로젝트에서 가장 흔한 갈등은 **무임승차(free-riding)** 입니다.

- "다음 주에 올릴게요"가 반복되다가 마감 직전에 몰아치기
- 기여도가 다른데 **같은 점수**를 받는 구조 → 열심히 한 사람의 동기 저하
- 교수님께 말하자니 증거가 없고, 말 안 하자니 억울함
- 역할을 나눠도 "검토", "취합"처럼 **검증 불가능한 역할**이 생김

기존 도구(노션·카톡)는 **기록**은 되지만 **약속을 강제하지도, 공정하게 평가하지도** 못합니다.

## 2. 해결 — 팀플 서약

| 단계 | 사용자 행동 | AI/시스템이 하는 일 |
|---|---|---|
| ① 팀 등록 | 수업 이름, 팀 이름, 구성원, 과제, 기간 입력 | **역할 설계 AI**가 "매주 검증 가능한 산출물" 단위로 역할과 주차별 목표를 자동 설계 |
| ② 주간 제출 | 매주 자신의 작업물(텍스트+링크+파일) 업로드 | **유사도 검사**(지난주 재탕·다른 팀원 복붙·링크만 변경 감지) → **검토 AI**가 4개 축(관련성·완성도·노력·명확성)으로 채점 → **판정 AI**가 *인정 / 조건부 인정 / 미인정* 판정. "열심히 했어요" 같은 **형식적 제출과 복붙은 미인정** |
| ②-1 주간 브리핑 | 팀 보드에서 버튼 한 번 | **브리핑 AI**가 이번 주 해낸 일, 위험 신호, **누가 누구를 기다리는지**, 다음 주 집중할 것, 단톡방 공지문을 생성 |
| ③ 미제출 팝업 | 마감이 지나도 안 올리면 팝업: **"팀의 평화를 부수겠습니까?"** | **아니요** → 기회로 **하루 연장**(주차당 1회) / **예** → "혼자 F를 받는 것에 동의한다는 건가요?" (예 / 뒤로가기) |
| ④ F 동의 | 최종 "예" 선택 | "F를 받는데 동의하셨습니다" 표시, 팀 보드에서 **이름 흑백 처리** + 문구 *"F를 받겠습니다. 교수님께 따로 말씀드리는 것에 동의합니다."* |
| ⑤ 리포트 | 학기 말 버튼 한 번 | **리포트 AI**가 제출 기록·판정 점수·연장/F 이력으로 **교수 제출용 기여도 보고서 + 동료평가 초안 + 독려 메시지** 생성 |

## 3. Multi-AI 파이프라인

```
과제 설명 ──► [1] 역할 설계 AI (Planner) ──► 팀원별 역할 + 주차별 산출물 목표
                                                     │
주간 제출물 ──► 유사도 검사(재탕·복붙) ──► [2] 검토 AI (Reviewer) ──► [3] 판정 AI (Gatekeeper) ──► 인정/조건부/미인정
                                                     │
이번 주 기록 ──► [4] 주간 브리핑 AI (Briefing) ──► 해낸 일 · 위험 · 의존 관계 · 공지문
                                                     │
전체 기록 ──► [5] 리포트 AI (Reporter) ──► 기여도 % · 보고서 · 동료평가 · 독려 메시지
```

- 모든 호출은 **OpenAI Chat Completions 호환** 형식 → OpenAI / Groq / Gemini / **틸론 GPU 로컬 모델**을 설정만 바꿔 사용
- 각 단계는 **JSON 스키마 강제** + 파싱 복구 로직으로 안정성 확보
- API 키가 없어도 **규칙 기반 모드**로 모든 기능이 끝까지 동작 (심사 중 네트워크 장애 대비)
- 모든 AI 호출의 시스템 프롬프트·입력·원문 응답을 DB에 기록 → 「프롬프트 기록」 탭

## 4. 교내 GPU(틸론) 활용

단톡 내용·과제물 같은 **학생 개인정보를 외부 API로 보내지 않기 위해**, 교내 틸론 GPU VM 에서 한국어 오픈 모델(EXAONE-3.5-7.8B)을 vLLM 으로 서빙하고 앱이 그 엔드포인트를 사용합니다.
설치 명령과 연결 방법은 **[docs/tilon_gpu.md](docs/tilon_gpu.md)** 참고.

## 5. 실행 / 배포

```bash
pip install -r requirements.txt
streamlit run app.py
```

### Streamlit Community Cloud (무료, 약 1분)
1. 이 저장소를 GitHub 공개 저장소로 push
2. https://share.streamlit.io → New app → 저장소/`app.py` 선택 → Deploy
3. (선택) **Settings → Secrets** 에 키 입력 → 바로 AI 모드
   ```toml
   GROQ_API_KEY = "gsk_..."          # 또는 GEMINI_API_KEY / OPENAI_API_KEY
   # 틸론 GPU 서버를 쓸 때
   TILON_API_KEY = "EMPTY"
   TILON_BASE_URL = "http://<틸론VM-공인IP>:8000/v1"
   ```

### 환경 변수 (로컬)
`GROQ_API_KEY`, `GEMINI_API_KEY`, `OPENAI_API_KEY`, `TILON_API_KEY`, `TILON_BASE_URL`, `TEAMFAIR_DB`(DB 경로)

## 8. 확장성

- **LMS 연동**: 교수 계정에서 전체 팀의 기여도 리포트 열람
- **Supabase/Postgres** 로 저장소 교체 시 멀티 캠퍼스 운영 가능 (db.py 만 교체)
- 깃허브 커밋·노션 변경 로그 자동 수집 → 제출 없이도 기여 증빙
- 기업 신입 OJT·공공기관 TF 등 "소규모 협업 + 공정 평가"가 필요한 모든 현장에 적용
